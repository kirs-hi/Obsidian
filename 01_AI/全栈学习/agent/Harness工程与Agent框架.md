# Harness 工程与 Agent 框架

> 来源：大模型 Agent 应用开发学习指南

## 1. 提示词工程技巧

提示词技巧分为单轮和多轮两种层次。

### 单次技巧

1. 要明确直接：减少闲聊类语言结构，让指令包含了明确的任务、上下文信息、参考等。
2. 将提示词拆分成更短的句子，让使用者在使用时方便修改，拆分成更细的、各自管控的句子。
3. 要记录不同的尝试，写量化的对比。
4. 引入结构化条件。

### 多次技巧

1. **Prompt Chaining**：将多个提示词串联起来，每一步的输出作为下一步的输入，从而构建一个多步问题的完整流路。
2. **Chain of Thought Prompting**：引导模型更多思考，通过在提示中加入处理过程，让模型在自己推理时能同时追踪出问题的每个步骤，而不是直接出答案。
3. **Tree of Thought Prompting**：分散给多个下行的路径或方案，确保行动路径有多条选择，然后选择最优路径。

## 2. Harness Engineering

### 2.1 概念定义

**一句话定义**：Harness Engineering 是指给 AI 模型构建"运行环境与管控层"的工程实践，目的是让 AI Agent 在协同时，具备权力、多专题驱动的应用能力、可控、且点面结合的性能表现。

**核心思路：从"马匹"理解 Harness**

Harness 本意是马具——套在马匹身上用于控制方向和力度的装备。类比到 AI：

- 大模型 = 一匹倔马：能力看似强大，但如果任由它自行行事，会发散思路，产生崩溃，无法按意愿前进
- Harness = 那套马具：束缚和控制，给大模型施加约束的系统

**公式**：**Harness = Agent - Model**

一个完整的 Agent 剔除大模型本身，剩下的所有东西都叫 Harness。

### 2.2 演进脉络

| 阶段 | 时期 | 描述 | 人的角色 | 难度 |
|------|------|------|------|------|
| Prompt Engineering | 2023-2024 | 如何把 Prompt 设计得精确（一句话把控） | One | 低-中低 |
| Context Engineering | 2025 | 加入 Context（Prompt、任务结果、Org 等内容）给出上下文 | 后缘一部分完全 | 中 |
| Harness Engineering | 2026 | 已经和 Agent 一起开始工程化 | DVPS | 低-中 |

三者递进关系：Harness 内部的每个 session 需要做好 Context Engineering，每次发给模型的 prompt 仍始终属于 Prompt Engineering。

### 2.3 Harness 工程实践要点

**核心工程件包括：**

- **子 Agent 集群（Swarm）**：一些大主/虚显直接领导面的小模型分别干了工作，背靠一个大模型智库序列指导
- **技能文件（Skills）**：一种高互动到的专用的指南，Agent 们通过与当面任务相关的工具配和技能（相较不应该 30 个工具）
- **Guard Rails + Checkpoints**：在关键节点自动达标的特等，忽达 Agent 最面快速
- **Handoffs**：session 之了面随的面段设文件，git commit 等着面的状态达，实到面 session 功复面等
- **Human-in-the-loop**：在关键的和危险的让人了解地方之达，让外面 AI 与达进到面了文达
- **复杂任务**：通过 Arch/Unit 等框架发将更多 Agent 车间代代的面能更新的发前到面
- **起达记忆 Agent**：定期从 时情等它代码风面格和文件也中的不一到也的、试从真正反面确达

**关键工程原则：**

- **轻量化，力删即简**：不要过量输入去全部塞进去，保留能影响到的核心逻辑就好（Manus 6个月反复回面、Vercel 砍掉 80% 产工二面场点费时）
- **模型无关性**：Harness 下挂什么模型都可以，别的模型也可以来用这种格式
- **将 Harness 视为数据架**：客户 Agent 实践、选移、分享都拥有通行目标类型，利于迭代优化

### 2.3.3 最佳实践建议

**1. 循环范式**

- 推荐广用途：走过 "loop 模型照到面 Ralph Wigum"：回到让这型变先定义"先做在用固定位确 X，仅变换 Y 就运从达"，再到面——让它用实到面等每 10 个面 "增到" 5~10k tokens。
- 任务变 2-3 步发展行结：重新让任务为"先 plan，再 execute，应步的做 plan"。深等一个从也不面定它到 plan，反回续回做面面等。
- **TDD 广用**"先面试，后代码"：让 agent 先写好测试让面补也到达，高利发写会之后，反让它合会让面识让从之面有bug直到达面面面面。

**2. 工具 I/O 卫生**

- 所有工具精出/加那断：默认仅保面过 2000 行 / 50KB；长 stack trace 只器结面模面：自行的输出 > 6MB 花那面确品达文件达：agent 报从等做结面面面面面。
- 建议反面器到"短面那里"：有其正面然结 traceback 逻那达多，不给让 harness 给从面 error type + 出确文件开面 + 再让仅面一仅也 → 文做的/所表结它名面。

**3. 结构性约束**

- 写死结构的常达 system prompt：规控"自文件 ≤ 200 行"/"函数从 ≤ 50 行"/"面让确然让则必须也从面然达到"——面到然 agent 分机不面然让达。
- 让达的在 OpenAI 面然结 "developer = manager"——每不再类面和每一行，面确从也然成完面确实面面面面。

**4. 安全护栏**

- 安全达面 sandbox 面面结然 agent：容器 / VM / devcontainer 三选一。裙裁限让的面 ".env"、".ssh"、然定面 cookie 只是面然达 agent。
- 三层级面自名单：🟢 自达出行类：读文件、类别面然面面、git diff → 🟡 需类然从面面到：写文件、安装依从然 → 🔴 运结人工面面达：rm -rf、git push --force、然削去达面从、达去面类面让类 → 保但然人工面面。

## 2.4 Harness 思想的应用

直接依据来源：Raj 的 "Engineering Coding Harnesses Deep Dive" 视频精讲。

从以下行为方面分步：**Retrieval / Context & Memory / Loops & Tools / Orchestration** 元部分来拆解 Harness 工程框架。

### 2.4.1 Retrieval（检索）

#### 检索工具对比

| 工具 | 场合 | 功能 | 费用/评语 |
|------|------|------|------|
| grep | 大量精确、快、类似的 | 文件夹子结构上/路径匹配全 | 默认选择：几百MB + 5GB / 文件夹 < 10w |
| BM25 (倒排索引) | 自然句、在类进很有区别 | 分词比则面的确 | 文件 > 5GB 或文件数 > 10w, grep 一次看 > 5s 时用 |
| Semantic Search (embedding) | "physician = doctor" 这类同义语义 | 表 & chunk 结语义检索 | 需要面索引/匹配同义词场景 |
| Agentic RAG（混合） | 目前位以/进来 query 代操进 | 比 Opus / GPT-5 配置级别 | 花 token 但能精准 |
| 结构化数据 / 元数 | join 关联、形状 join | metadata join（author / 时间 / 分类等） | 文件多元数据才需要 |

#### 最佳实践

- **默认 grep 起手**：90% 时代码都能 grep 到，不要一上来就 Plan
- **代码库 > 5GB 或文件数 > 10w**：加 BM25，快速轮转成一个 SKILL（长交 "biggrep --index" 或方面 BM25 码）
- **语义面/模型式查找不要用 embedding**：比如当"用"面类因同义替代时，类在 "auth/login/session" 等场景上用 semantic search
- **面对复杂（OpenGPT-5 级别）**：转上 Agentic RAG，让模型自己能写 query，在文本做自动切分 chunk
- **什么时候用结构化面数据**：如查"author + commit 时间 + 那些的步骤"这种 metadata join 时，才不要限制在纯文件检索

### 2.4.2 Context & Memory（上下文与记忆）

#### 三层记忆模型

| 层级 | 名称 | 定义 | 生命周期 |
|------|------|------|------|
| Layer 1 | Active Context Window（当前上下文） | 当前送给模型的 token 内容 | 一次会话内 |
| Layer 2 | Working State（临时工作文件） | todo.md / plan.md 等临时中间状态 | 一次任务内 |
| Layer 3 | Durable Memory（持久化长期记忆） | AGENTS.md、Skills、跨 session 记忆 | 永久 |

**Layer 1：Active Context Window**

就是当前一轮推理的 token 窗口。它只能"现在"——一次交互中可见。因为有 sliding window 和 compaction 机制，旧内容会被压缩或丢弃。

**Layer 2：Working State**

- 长任务先写一个 todo markdown：把计划落在 `plan.md` / `todo.md`，让 agent 每完成一步勾选
- 确保直接在上下文中可见：中间步骤的文件用 Recursive Language Models 模式
- 任务结果双重归档：working files 是一次性的，任务完成后归档到 durable memory

**Layer 3：Durable Memory**

跨会话留下来的持久化信息，下次开始会话也在。两种主要形态：
- AGENTS.md：存放项目配置信息（构建命令、目录结构等），主要由 harness 启动会自动读入 system prompt
- Skills：每个 SKILL 文件代表了一种 Agent 掌握的持久技能/记忆的发现模式

三层是自下而上递进的：实在不了 → 永结性的 working files → 任务结束后归档为 durable memory。

#### 最佳实践

**Active Context Window 管理：**
- 主动管理上下文，不要等到 compaction 丢失信息
- 使用 `/compact` 主动触发压缩（Claude Code）
- 走遍用 Rewind（双击 ESC）直接取回之前的重要的上下文

**Working State 管理：**
- 长任务先写 todo markdown
- 确保中间状态可见
- 任务完后及时归档

**Durable Memory 管理：**
- AGENTS.md 铁律：只放项目本身的事实，不放通用的规范
- Skill 判定标准：同一类操作做了 3 次以上 + 步骤超过 5 步 + 都能模型总会错一小时就达这三个条件考虑写 Skill
- 每个 Skill 必须配 eval：准备一个小评测，定性做 with skill vs without skill 两对照

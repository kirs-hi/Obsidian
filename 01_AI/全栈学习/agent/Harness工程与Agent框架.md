# Harness 工程与 Agent 框架

## 1. 提示词工程技巧

提示词技巧分为单轮和多轮两种层次。

### 单次技巧

1. 要明确直接：减少闲聊类语言结构，让指令包含了明确的任务、上下文信息、参考等。
2. 将提示词拆分成更短的句子，让使用者在使用时方便修改，拆分成更细的、各自管控的句子。
3. 要记录不同的尝试，写量化的对比。
4. 引入结构化条件。

### 多次技巧

1. **Prompt Chaining**：将多个提示词串联起来，每一步的输出作为下一步的输入，从而构建一个多步问题的完整流路。
2. **Chain of Thought Prompting**：引导模型更多思考，通过在提示中加入处理过程，让模型在自己推理时能同时追踪出问题的每个步骤，而不是直接出答案。
3. **Tree of Thought Prompting**：分散给多个下行的路径或者方案，确保行动路动一些路径，然后选择最优路径。

## 2. Harness Engineering

### 2.1 概念定义

**一句话定义**：Harness Engineering 是指给 AI 模型构建"运行环境与管控层建构"的工程实践，目的是让 AI Agent 在协同时，具备权力、多专题的驱次提出的应用、可长、点面性能操作。

**核心思路：从"马匹"理解 Harness**

Harness（安全带/马具）——面在马匹上面联设的物件起到监控作用，比较温稳、约束面、与大多更智遗留大，让马匹向力方向产生端编控制，让它少失控。

把这个类比转到 AI 领域：
- 大模型 = 一匹倔得马：官方看视，如知事行自行设计时，会发散思路，产生崩塌，无法按意愿前往的结果。
- Harness = 那套马具：束控制，给大模型的新系统。

**公式**：Harness = Agent - Model

换句话说，一个完整的 Agent 剔除掉大模型，剩下的所有东西都叫 Harness。Harness Engineering 是实践缩略论，本质来都是产严格的定义。

### 2.2 演进脉络

| 阶段 | 时期 | 描述 | 难度 |
|------|------|------|------|
| Prompt Engineering | 2023-2024 | 如何把 Prompt 设计得精确 | 低-中低 |
| Context Engineering | 2025 | 加入 Context（Prompt、任务结果、Org等内容）给出前缀上下文 | 中 |
| Harness Engineering | 2026 | 已经和 Agent、Harness 一起开始工程化 | 低-中 |

三者递进关系：Harness 内部的每个 session 对应整套 Context Engineering，每次发给模型的 prompt 仍始终属于 Prompt Engineering。

### 2.3 Harness 工程实践要点

- **外部持久记忆**—用文件系统（JSON, Markdown, git log）代替模型内部记忆，解决"失忆"问题。
- **错误处理或自愈**—一个 Core 发现错误，先完成纠错门槛，AI 实际面则走准确方向达成修复（"问您能解决切己如完成规范"）
- **种子比较 + 上下文如策**—每个 Agent 只做一个心比较基确，有 Agent 从下来达直面前，但则转到 Context 层的前面外前。

### 关键工程原则

- **轻量化，力删即简**：不要过量输入去全部塞进去，保留能影响到对的核式（Manus 6个月反复面回、Vercel 砍掉80%产工二面场点费时）
- **模型无关性**：Harness 下挂的什么模型，别的模型也可以来吃这种到格式
- **将 Harness 视为数据架**：客户 Agent 实践、选移，分享都拥有通和目标类型，利于迭代优化。

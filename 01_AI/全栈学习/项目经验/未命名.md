## 方案：先全貌，再拆解——像看地图再逛街区

### 1. 先搞明白这是个什么东西（10分钟）
我带你**打开线上页面**，对着屏幕指：

- 顶部导航栏 → 对应 `TopNav.tsx`
- 左侧考点目录 → 对应 `Sidebar.tsx`
- 中间真题墙格子 → 对应 `QuestionWall.tsx`
- 底部柱状图 → 对应 `ScoreChart.tsx`
- 点击格子弹出弹窗 → 对应 `QuestionModal.tsx`
- 弹窗里的题目卡片 → 对应 `QuestionCard.tsx`

**目的**：让你知道页面上每一个东西，背后就是一个 `.tsx` 文件，心里有张"地图"。

---

### 2. 讲清楚三层结构：数据 → 逻辑 → 界面（15分钟）

用一张图：

```
┌──────────────────────────────────────────────┐
│  Supabase 数据库（存题目、考点、评论.....）   │  ← 数据层
└──────────────────┬───────────────────────────┘
                   │ api.ts / useExamData.ts   ← 取数据
                   ↓
┌──────────────────────────────────────────────┐
│  React 组件（把数据变成页面）                 │  ← 界面层
│                                              │
│  IndexPage → Sidebar / QuestionWall          │
│           → QuestionModal → QuestionCard      │
│                            → AnswerPanel      │
│                            → CommentSection   │
└──────────────────────────────────────────────┘
```

**不深入代码**，就是让你理解：**数据从数据库出发，经过 API 取出来，最后被 React 画成页面。**

---

### 3. 同层级对比："回答卡片"和"评论卡片"结构一模一样，核心组件复用（10分钟）

我们把 `answer`、`explanation` 称为“卡片内容”，`AnswerPanel`、`CommentSection` 称为“卡片容器”。无论是要展示答案、解析还是评论，核心模式都一致：

- 有个**标题/标签**（答案 / 解题解析 / 评论区）
- 有个**内容区域**
- 可能带**背景色块**（绿底 / 橙底 / 灰底）

对应代码也是同结构——这为将来抽象成通用组件打下基础。

### 5. 面向未来的前端开发

最后我会带你打开一个“**更高维度**”的视角：

- 前端早已不是画页面那么简单，它是 **数据 → 状态 → 界面** 的完整链路。
- 你现在学习的不仅是 React 语法，而是在理解：**用户看到的一切，都源于一个状态的改变。**
- 这个项目的真题墙、刷题弹窗、评论系统，背后遵循的都是同一套心智模型——未来你要做任何交互界面，都能复用这套模型。

而且 Next.js 也帮你做了“**服务端渲染**”（SSR），就是你打开网页的第一瞬间，内容就已经在服务器上生成好了，不需要等浏览器再慢慢拼接，这样对考研学生来说，打开速度更快，体验更好。

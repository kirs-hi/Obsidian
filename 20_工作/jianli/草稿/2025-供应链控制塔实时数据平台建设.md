介绍话话术


## 正式版本
**项目背景：** 公司硬件供应链涉及 13 个业务子系统，供应链控制塔（SCCT）定位为一线作战工具，数百名一线人员依赖实时数据做操作决策，对数据的贯通性、时效性和准确性要求极高。

**技术栈：** Flink / Flink SQL、Apache Paimon（deduplicate/aggregation merge-engine、sequence.field、Changelog 流读、Lookup Join）、Kafka/Mafka、Doris、Spark SQL、HDFS

**职责描述：** 负责控制塔实时数据平台的整体架构设计与核心场景落地，包括全链路数据贯通、实时监控与预警、指标体系建设，以及数据质量和链路稳定性保障体系的搭建。

**技术方案：**

- **全链路数据贯通与统一底座：** 13 个子系统 Binlog 通过 Flink CDC 写入 Paimon 主键表（deduplicate + sequence.field）实现自动去重与乱序过滤，维表统一收口至 Paimon 通过 Lookup Join 关联，替代原 ROW_NUMBER + Redis + 三套维表存储的方案，Checkpoint 下降 75%，Kafka Topic 减少 40%。
    
- **采购执行实时监控与异常预警：** 基于 Paimon Changelog 流读消费采购订单变更数据，对交期延迟、到货差异、质检异常等关键节点实时规则预警，同时支持 Time Travel 按时间点回溯订单状态，替代原 T+1 报表发现问题的模式。
    
- **库存实时水位监控与预警：** 采用 Paimon Aggregate Table（SUM/LAST_NON_NULL）替代 Flink Cumulate Window，库存增量事件写入时自动合并计算实时水位，Flink 端无状态写入，Checkpoint 下降 90%，下游消费 Changelog 触发补货/积压预警。
    
- **供应链实时指标体系与决策支撑：** DWS 层按指标域建立 Aggregate Table 统一聚合采购履约率、库存周转、设备在线率等跨域指标，ADS 层同步至 Doris 提供 OLAP 查询，配合 Spark SQL 每日批处理修数，修数时间从小时级缩短至分钟级。
    
- **实时数据质量保障体系：** 建设写入层（Paimon 去重+乱序过滤）、加工层（实时对账）、产出层（实离对账，差异率 < 0.05%）三层校验体系，设计分场景修数 SOP（Spark SQL 直接修复 Paimon 表 + Flink 指定时间戳恢复），修数资源消耗降低 80%。
    
- **链路稳定性与运维保障：** 建设全链路系统+业务双层监控，制定 3-10-15 分钟故障响应 SOP。引入 Paimon 后链路组件从 7 类收敛至 4 类，Flink 去重/聚合等逻辑下沉存储层实现无状态化，故障恢复速度提升 70%，核心链路稳定性 99.9%。
    

**项目成果：**

- 打通 13 个子系统数据，构建供应链全链路统一实时数据底座，支撑控制塔一线作战看板上线
- Flink 去重算子 State 降为零，相关任务 Checkpoint 大小下降 75%
- 聚合类任务 Checkpoint 大小下降 90%，任务恢复速度提升 70%
- Kafka Topic 数量减少 40%，中间态数据从不可查变为支持 SQL 点查和时间旅行
- 修数时间从小时级缩短至分钟级，修数资源消耗降低 80%
- 链路组件从 7 类收敛至 4 类，外部组件依赖减少 60%
- 实时与离线数据差异率 < 0.05%，核心链路稳定性 99.9%

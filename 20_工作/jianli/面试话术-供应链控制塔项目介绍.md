
# 供应链控制塔实时数据平台 — 面试项目介绍话术（5分钟）

> 时间分配：开场定位 40s → 核心挑战 30s → 架构方案 2m20s → 成果 50s → 收尾 20s
> 目标字数约1200-1300字，练习时控制在4分30秒-5分钟之间。

---

## 话术正文

我介绍一下供应链控制塔实时数据平台这个项目。

我们公司的硬件供应链覆盖采购、仓储、物流、维修、交付全链路，底层有 13 个业务子系统。业务分两种形态：销售类，像骑行设备、充电宝，走采购入库出库交付的流程；资产运营类，设备投放之后要运维、回收、报废，是全生命周期管理。供应链控制塔是这些业务的统一数据作战台，不是给管理层看报表的驾驶舱，而是一线仓管、采购员、物流人员每天盯着干活的工具，有几百号人在用。我负责整个实时数据平台的架构设计和核心场景落地。

这个项目面临三个核心挑战：一是 13 个子系统数据要贯通到统一视图，二是一线人员依赖实时数据做操作决策、时效性要求极高，三是数据必须准确，一线人员看到矛盾数据就不信任系统。

针对这些挑战，我的整体思路是引入 Paimon 构建流式湖仓，把原来散在 Flink State、Redis、Kafka 各处的状态管理统一下沉到 Paimon 存储层。具体落了六个场景。

第一个是全链路数据贯通，这是整个平台的底座。13 个子系统的 Binlog 通过 Flink CDC 写入 Paimon 主键表，用 deduplicate merge-engine 加 sequence.field，写入时自动按 event_time 去重和过滤乱序，Flink 端完全不需要维护去重状态。原来去重靠 ROW_NUMBER 加 Redis，State 膨胀严重，现在全省了。维表也做了收口，原来散在 Redis、Cellar、MySQL 三套存储里，现在统一到 Paimon，事实表通过 Lookup Join 本地查找，不走网络。这个场景做下来，Checkpoint 下降了 75%，Kafka Topic 减少了 40%。

第二个是采购执行的实时监控。基于 Paimon Changelog 流读消费采购订单变更，对交期延迟、到货差异、质检异常做实时规则预警，替代原来 T+1 才发现问题的模式。

第三个是库存实时水位监控。用 Paimon Aggregate Table 替代 Flink Cumulate Window，库存增量事件写入时自动合并计算水位，Flink 无状态写入，Checkpoint 下降了 90%，下游消费 Changelog 触发补货和积压预警。

第四个是统一指标体系。DWS 层按指标域建 Aggregate Table，统一聚合采购履约率、库存周转、设备在线率等跨域指标，同步到 Doris 做 OLAP 查询。配合 Spark SQL 批处理修数，修数从小时级压到了分钟级。

最后两个是横向能力。数据质量建了三层校验——写入层靠 Paimon 保证去重和乱序过滤，加工层做实时对账，产出层做实离对账，差异率控制在万分之五以内。稳定性方面，链路组件从 7 类收敛到 4 类，Flink 去重和聚合逻辑下沉存储层实现无状态化，故障恢复速度提升 70%，做了 3-10-15 分钟的故障响应 SOP，核心链路稳定性 99.9%。

总结一下成果：业务上打通了 13 个子系统，支撑控制塔一线作战看板上线。技术上关键数字是 Checkpoint 下降 75% 和 90%，Kafka Topic 减少 40%，修数从小时级到分钟级，组件从 7 类收敛到 4 类，实离差异率万分之五以内。最本质的变化是把状态管理从计算层下沉到了存储层，Flink 变成了无状态的编排层，任务更轻、更稳、恢复更快，中间态数据从 Kafka 黑盒变成了 Paimon 可查表。

这个项目里我觉得最有意思的是 Paimon 不同 merge-engine 的场景化选型，以及 Changelog 流读和 Kafka 消费在时效性和可查性上的取舍，如果您感兴趣我可以展开讲。

## 练习提示

1. **核心节奏**：前1分钟让面试官理解"你在什么业务里做什么事"，中间2分多讲"怎么做的"，最后1分钟讲"效果 + 钩子"。
2. **重点场景**：场景一（统一底座）和场景三（Aggregate Table）讲得最详细，场景二和场景四各一句话带过。
3. **数字记忆**：75%、90%、40%、70%、80%、99.9% 这6个数字要烂熟于心。
4. **收尾钩子**：最后一句引导面试官往 Paimon 技术细节追问——merge-engine 选型、LSM Tree 原理、Changelog 流读机制、批处理修数流程。
5. **如果时间紧**：砍掉场景二和场景四，直接说"另外还做了采购监控和指标体系，分别用了 Changelog 流读和 Aggregate Table"，省出30秒。
6. **如果面试官中途追问**：不要急着回到话术，顺着追问展开，剩下的场景可以简化为"除此之外还做了XX和XX"一句话收掉。
